# HealthPi Project Documentation

## Objective

HealthPi is a prototype for IoT vehicle health monitoring and diagnostics. It combines hardware sensing, cloud telemetry, machine learning, and notifications.

## Hardware-to-software relationship

The Arduino firmware reads temperature, humidity, pressure, throttle, runtime, and RPM-related values. It displays measurements on an LCD and periodically formats telemetry for the ThingSpeak channel.

The Python prediction service reads the latest ThingSpeak feed and selects four values for the ML model: engine temperature, runtime, throttle, and RPM.

## ML workflow

The dataset generator creates 1,000 synthetic vehicle records. Maintenance status is assigned using the rules in `ml/ds.py`. `ml/train.py` trains a Random Forest classifier using an 80/20 train/test split and saves the trained model as `vehicle_monitoring_model.pkl`.

## Notification workflow

`ml/pred.py` loads the trained model, fetches the latest ThingSpeak record, predicts a status, prints the status, and sends it to Telegram. It repeats every 20 seconds.

## Important prototype limitation

The current dataset is synthetically generated by rule-based logic. Therefore, model accuracy on this dataset should not be treated as evidence of real-world vehicle diagnostic accuracy. Real vehicle data, validation, calibration, and safety review are required before using such predictions for real vehicle decisions.
